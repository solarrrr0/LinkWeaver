# 链跃 LinkWeaver 0.3.7

项目与发布下载：<https://github.com/solarrrr0/LinkWeaver>

Windows 本地代理链路管理器。采用独立 Go 管理程序和 Mihomo 核心，使用“中转 → 固定出口 → HTTPS 目标”的完整链路延迟选路。数据保存在安装目录的 `data` 文件夹。

## 安装

运行 `LinkWeaver-Setup-0.3.7-Windows-x64.exe`，选择安装目录，按需勾选“登录 Windows 后自动启动到托盘”和“创建桌面快捷方式”。有 D 盘时默认建议 `D:\LinkWeaver`；也可自行选择可写目录。安装后主程序为安装目录中的 `LinkWeaver.exe`，桌面快捷方式会启动后台并打开网页管理页。支持 Windows 10/11 x64，不需要另外安装 Go、Python、Node 或原版 ChainPilot。

安装包不包含个人订阅、节点、密码和浏览器设置。新电脑需要自行配置节点/出口，或使用管理页导入自己导出的配置备份。覆盖安装保留现有数据；卸载移除程序、快捷方式和自启入口，并保留 `data` 中的个人配置。

## 打开和退出

双击安装后的 `LinkWeaver.exe` 或桌面快捷方式，网页管理地址为 `http://127.0.0.1:28180`。程序启动后会在 Windows 右下角通知区域注册绿色箭头图标；若任务栏没有直接显示，请展开 `↑` 隐藏图标区域，可以自行将其拖到常显区域。

单击托盘图标打开网页，右键可打开管理页、启动全部出口、停止全部出口或退出。关闭网页后后台继续运行。“设置 → 退出链跃”也可结束后台。重复启动会打开已有管理页，不启动第二个核心。启动选项可在设置中调整。开机启动使用当前用户“启动”文件夹中的 `LinkWeaver.lnk`，登录后等待 10 秒再恢复运行；再次保存设置会修复自启入口。旧版 Run 项会移除，避免重复启动。最近一次启动时间和来源记录在 `data/last-launch.txt`。

## 四个配置入口

1. **总览**：查看每个出口的运行状态、当前中转、完整链路延迟、本地代理端口和最近活动；可启停、测试、复制入口地址。
2. **出口配置**：添加、编辑、删除固定出口。支持节点链接解析，或通过协议、服务器、端口、用户名、密码、UUID、TLS 等字段填写。高级参数支持 JSON。认证信息留空保持原值；勾选“清除”后可清除旧认证。每个出口有独立本地 HTTP / SOCKS5 端口，可选择多个来源或全部来源，也可限制到明确勾选的候选节点，最多 8 个出口。
3. **中转池**：添加订阅、编辑名称/地址/请求标识/优先级、启停、刷新和删除来源；也可导入多条节点链接、Clash YAML/JSON 或 Base64 订阅内容。节点支持搜索、编辑、启停、删除、优先级、完整链路检测和手动选择。不同出口的检测结果独立显示。
4. **设置**：调整检查目标、超时、并发、刷新间隔；高级选项控制切换阈值及驻留时间；设置开机启动、恢复运行、打开网页；导出或恢复配置备份。

新用户配置顺序：**中转池添加订阅/节点 → 出口配置添加固定出口 → 启动出口 → 将应用代理指向这个出口卡片上的本地地址**。已经迁移的配置可直接使用。

出口卡片显示对应的本地代理端口。支持 HTTP 和 SOCKS5 的 TCP 连接。程序不会自动配置 Windows 系统代理或 TUN。关闭某个出口会断开它现有的连接。

## 导入 Clash

网页右上角提供“一键配置现有 Clash”和“复制 Clash 导入链接”。前者适用于本机 Clash Verge Rev：连接核心的命名管道或本地控制接口，在当前订阅的局部增强脚本中加入链跃本地入口，并追加到所有手动选择组。原规则、DNS、非手动策略组和当前选择保留，不会替用户选择新节点。原脚本会备份到 D 盘；重载或恢复选择失败时尝试回滚。当前订阅必须已经配置局部增强脚本；缺少脚本或控制接口不可用时显示原因和备用导入链接。

复制链接、下载 YAML 和备用“新增独立订阅”仍可使用。备用方式通过已注册的 `clash://install-config` 协议唤起客户端，仅表示请求已发出，需在客户端确认。它新增独立订阅，与原配置接入方式不同。上游密码、UUID、服务器和订阅地址不会导出；仅包含链跃出口名称和本地入口。

在原 Clash 手动策略组中按需选用“链跃 · …”，流量路径为 `Clash → 链跃本机 SOCKS5 入口 → 中转 → 固定出口 → 网站`。

链接只适用于当前这台电脑。链跃需要保持运行，停止出口后对应的本地代理不可用。导出地址含持久本地访问密钥，保存于 `data/clash-subscription.key`，重启后台后仍可更新订阅；分享便携包时不包含这个密钥。出口名称及本地端口会出现在导出 YAML 中。

## 连接策略

按来源或自定义分组（最多 20 组）。默认启用速度优先，跨组按完整链路评分比较；关闭后先比较组和节点优先级，再比较评分。暂停组只阻止新的自动选用，保留当前转发。

完整链路检查包含中转、出口和目标 HTTPS 请求。统一延迟默认开启，可在设置中关闭；它改变测量口径，不会消除实际握手耗时。评分考虑平滑延迟、抖动和失败率。切换要求达到绝对和相对改善阈值，并连续成功且满足驻留时间；当前链路连续失败会尝试备用。

中转池支持批量编辑、清除已退役节点及手动限量下载测速。测速比较当前线路与最多两条近期候选，每条最多下载 2 MiB，不自动切换线路。

候选切换前先走独立验证入口，完成实际 HTTPS 请求和最终出口 IP 检查。可选“预期出口 IP”开启严格 IP 一致性约束。没有已验证链路时入口阻断，不回退到直连。选路只影响后续新连接，不主动清理已有连接。

手动锁定会持久保存，停止时也能预设锁定节点；失败只告警，不自动切换或主动阻断当前转发。重新启动时必须先通过链路和出口校验；未通过时等待原锁定节点恢复。

中转池可独立检测中转本身，无需固定出口；完整链路延迟仍单独显示。刷新全部来源、独立检测中转、批量测试运行出口均显示后台进度并支持取消；同类任务复用一条状态，完成/取消结果 6 秒后收起，失败结果 15 秒后收起，空闲时整个任务区隐藏；取消会等待当前短请求结束。核心意外退出可自动恢复，恢复后重新校验出口。

每个出口运行独立核心。修改协议、认证、候选节点或测试目标可能使受影响的出口短暂重连；只改名称、优先级或检测间隔通常保留核心，其他配置未改变的出口保留连接。订阅刷新失败会保留旧节点，并显示错误。删除一个被指定的来源后，该出口保持空候选池，需要重新选择来源，不会自动使用其他来源。

后台每 5 秒检查任务调度和核心恢复条件。订阅默认每 360 分钟更新，直连请求失败时可通过本程序已连接的出口重试。相同节点保存多个来源归属，一个来源刷新或删除不会误删另一个来源仍提供的节点。订阅移除的节点标为退役；手动删除记录会阻止订阅刷新加回，显式重新导入可以解除排除。最多 2000 个中转节点。SS 带插件链接请使用完整 Clash YAML，以免丢失插件参数。

## 数据与迁移

`data/config.json` 保存全部配置，含个人认证信息。`data/config.previous.json` 是最近保存前的配置；升级前备份另存在 `data/backups`。`runtime/<出口ID>/core.json` 含核心密钥和代理凭据，不应公开。`data/metrics-<出口ID>.json` 保存测量记录。

常规状态 API 隐藏认证信息，编辑接口会返回用于编辑的服务器和端口，但不回显已保存的密码、UUID、私钥等认证字段。订阅地址留空保持原值，不回显原 URL。用户主动导出的备份含完整凭据，请自行妥善保管。

管理端只监听本机，检查 Host、Origin 和会话令牌。核心控制接口使用随机密钥。每个出口除用户代理端口外另占用验证和控制端口，新增出口时自动分配，配置时检查冲突。

`tools/import_chainpilot.py` 是旧版单运行出口的只读导入工具，需要原软件运行和 Python + PyYAML；默认拒绝覆盖已有配置。已有旧版配置升级时自动迁移为多出口格式。`tools/import_chainpilot_v2.py` 可在已有迁移配置上只读补充原数据库的来源信息和缺少的出口，保留一次性导入标记及备份。它不会修改原软件。`tools/import_chainpilot_v3.py` 在旧版迁移配置上补充原版分组、候选范围及多来源归属，先备份且只执行一次，已有 v3 策略不会被覆盖。

## 构建和发布

需要 Windows x64、Go 1.26.5 和 Inno Setup 7。执行 `build.ps1` 编译管理程序；`build.ps1 -RunTests` 可显式运行测试。开发缓存位于项目 `.tools`，不打入发行版。

将 Mihomo v1.19.29 的 Windows amd64 兼容版本放入 `bin/mihomo.exe`，对应源码已在 `licenses/mihomo-source-v1.19.29.zip` 中提供。`licenses/THIRD-PARTY-NOTICES.txt` 记录使用的核心摘要及组件许可证。主程序可执行图标资源为 `resource_windows_amd64.syso`；修改图标或 manifest 后，可使用 `github.com/akavel/rsrc` 重新生成。

执行 `tools/build-release.ps1` 生成安装 EXE、客户端更新 ZIP 和 SHA256。将这些文件上传到 GitHub 的正式 Release，标签使用 `v主版本.次版本.修订号`。更新 ZIP 必须保持 `LinkWeaver-Update-版本-Windows-x64.zip` 命名，并同时上传同名 `.sha256` 文件。版本号同时维护于 `update_windows.go`、安装脚本、manifest 及页面显示中。

## 程序升级

每次打开管理页自动检查 `solarrrr0/LinkWeaver` 的 GitHub 最新正式 Release，页面有“检查更新”和“下载并安装更新”入口。发现新版时也会在管理页顶部提示。只检查不会主动中断代理；点击下载安装后，后台下载 ZIP，核对整个包的 SHA256、GitHub 资产摘要（如提供）、包内文件哈希和 Windows x64 格式，再替换程序与核心并重启。

更新下载优先使用当前系统的本地代理或本程序已连接的出口，也支持直连 GitHub。客户端不需要 GitHub 账号或令牌；项目必须公开。检查失败会显示原因，不会把连接失败当成“已是最新版”。

更新保留订阅、节点、出口及设置，保留最近一次回退备份；新版未通过启动检查时尝试恢复旧程序与配置。下载失败或校验不符时不替换现有程序。离线 ZIP + SHA256 升级入口及程序回退入口仍保留。更新时代理会短暂断开。

## 当前边界

支持 Windows 托盘、多出口、订阅、手动节点、优先级、检测、自动/手动选路和本地备份。本地入口目前提供 TCP；暂未实现 UDP、TUN 和云同步。本次未发现原版把 UDP/TUN/云同步作为管理器功能，不能据此将这些列为已确认的原版缺失项。Clash 原配置接入以 Verge Rev 和已有局部脚本为适用条件，其他客户端请用独立订阅方式。原 ChainPilot 保留，可以并行运行。

界面依照用户提供的导航及使用流程重新实现，未取得或直接复制 ChainPilot 的业务源码。独立运行的 Mihomo v1.19.29 核心及对应源码、GPL-3.0 和其他依赖许可证均保存在 `licenses`。
